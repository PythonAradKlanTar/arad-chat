# ARAD CHAT — بسته توسعه نسخه ۰٫۵

این بسته یک پایه اجرایی واقعی برای ادامه ساخت پیام‌رسان است؛ **نسخه نهاییِ همه امکانات نیست**. لطفاً آن را به‌عنوان محصول کامل یا آماده انتشار عمومی معرفی نکن.

## امکاناتی که در کد فعلی کار می‌کنند
- ثبت‌نام با ارسال OTP ایمیل از Supabase و تأیید کد در سرور Supabase Auth
- تعیین نام، یوزرنیم یکتا و رمز پس از تأیید ایمیل
- ورود با ایمیل و رمز عبور
- درخواست بازیابی رمز با ایمیل و ثبت رمز جدید از لینک بازیابی
- یک حساب برای هر ایمیل (قید یکتایی ایمیل در Supabase Auth)
- استفاده از یک حساب روی چند دستگاه (sessionهای مستقل)
- پروفایل پایه، جست‌وجوی کاربران و گفت‌وگوی خصوصی متنی زنده با Realtime
- تابع Edge نمونه برای عملیات امن مالک/مدیر: بن موقت/دائمی، رفع بن، اعطا/لغو تیک و پریمیوم با ثبت لاگ

## امکاناتی که به سرویس یا توسعه مستقل نیاز دارند
اعلان Push در زمان بسته بودن سایت، اجرای امن ربات‌ها، فروشگاه اجرایی ربات، پاک‌سازی فیزیکی خودکار پیام‌های منقضی. تماس P2P و زمان‌بندی سمت سرور در نسخه ۰٫۴ به‌صورت اولیه اضافه شده‌اند و نیازمند راه‌اندازی و تست هستند.

## راه‌اندازی
1. Node.js نسخه LTS را نصب کن.
2. در Supabase یک پروژه بساز.
3. از SQL Editor به‌ترتیب اجرا کن: `supabase/schema.sql`، `supabase/modules_schema.sql`، `supabase/admin_schema.sql`، `supabase/migrations/001_signup_security.sql`، `supabase/migrations/002_free_features.sql` و `supabase/migrations/003_free_fixes.sql` سپس `supabase/migrations/004_devices_calls_groups_scheduler.sql` و در آخر `supabase/migrations/005_call_signaling_hardening.sql`.
4. در Authentication > Providers، ورود Email را فعال کن و Email OTP را پیکربندی کن. برای تحویل واقعی ایمیل در محیط عمومی، SMTP معتبر خودت را تنظیم کن؛ سهمیه رایگان محدود است.
5. در Authentication > URL Configuration، آدرس سایت و Redirect URL را تنظیم کن.
6. `.env.example` را به `.env` تغییر نام بده و URL پروژه و کلید عمومی (anon/publishable) را وارد کن. کلید service_role را هرگز در فایل فرانت‌اند نگذار.
7. اجرا: `npm install` سپس `npm run dev`.

## فعال‌کردن توابع مدیریتی
توابع `admin-action`، `admin-dashboard` و `admin-console` را با Supabase CLI منتشر کن: `supabase functions deploy admin-action`، `supabase functions deploy admin-dashboard` و `supabase functions deploy admin-console`. تابع جایگزین زمان‌بندی `scheduled-dispatch` فقط وقتی pg_cron در دسترس نیست لازم می‌شود. مقادیر `SUPABASE_URL`، `SUPABASE_ANON_KEY` و `SUPABASE_SERVICE_ROLE_KEY` را فقط در Secrets سمت Supabase Functions قرار بده؛ کلید service_role هرگز نباید وارد `.env` فرانت‌اند شود. ابتدا حساب مالک را در Auth بساز، ایمیلش را تأیید کن، سپس فایل `supabase/OWNER_BOOTSTRAP.sql` را باز کن، ایمیل تأییدشده مالک از قبل در فایل روی arezopourahmad902@gmail.com تنظیم شده است؛ پس از ساخت و تأیید همین حساب، SQL را در SQL Editor اجرا کن. هیچ رمز ثابت یا شناسه مالک در کد عمومی قرار نده.

## قابلیت‌های رایگان اضافه‌شده در این بسته
- رابط سه‌ستونه واکنش‌گرا با تم روشن/تاریک و نسخه قابل نصب PWA (پوسته برنامه هنگام آفلاین باز می‌شود؛ ارسال پیام آفلاین نیست).
- تب آرشیو و بازگردانی گفتگو؛ مرتب‌سازی گفتگوهای سنجاق‌شده.
- پیش‌نمایش عکس/ویدئو/صوت و ضبط ویس از میکروفون مرورگر.
- نمایش متن پیام پاسخ‌داده‌شده، حذف نرم پیام، حذف از Saved Messages و ارسال موقعیت با لینک نقشه.
- اعلان مرورگر هنگام دریافت پیام وقتی سایت باز و در پس‌زمینه است؛ اعلان Push در زمان بسته بودن سایت پیاده‌سازی نشده.
- فعال‌سازی/غیرفعال‌سازی TOTP با Supabase MFA و چالش کد هنگام ورود؛ خروج از نشست‌های دیگر با قابلیت Auth.
- RPC امن برای سنجاق/آرشیو تا کاربر نتواند با تغییر مستقیم رکورد، نقش عضویت خودش را ارتقا دهد.
- داشبورد پایه آمار و صندوق گزارش برای مالک/مدیر از طریق Edge Function.

## قابلیت‌های نسخه ۰٫۴
- پنل مدیریتی چندبخشی: کاربران/مدیران، بن و رفع بن، تیک و پریمیوم، گروه/کانال، فهرست ربات‌ها، گزارش‌ها، پیام همگانی درون‌برنامه‌ای، کد دعوت، آمار، سوابق و تنظیمات عمومی. عملیات مدیریتی از Edge Function `admin-console` عبور می‌کند و نقش مالک برای تغییرات حساس لازم است.
- مدیریت اعضای گروه/کانال از طریق RPC امن: افزودن، حذف، ارتقای مدیر، عزل مدیر و تغییر عنوان/توضیحات. ارسال پیام در کانال به مالک/مدیر محدود شده است.
- فهرست دستگاه‌های شناخته‌شده برنامه با زمان آخرین مشاهده و شناسه محلی؛ این فهرست گزارش دستگاه‌های استفاده‌کننده از برنامه است، نه فهرست کامل refresh-tokenهای داخلی Supabase Auth. برای ابطال نشست‌ها از قابلیت signOut سایر نشست‌ها استفاده می‌شود.
- تماس یک‌به‌یک آزمایشی صوتی/تصویری با WebRTC و سیگنال‌دهی Realtime. از STUN عمومی Google استفاده می‌کند؛ در بعضی شبکه‌ها بدون TURN رایگان/اختصاصی اتصال برقرار نمی‌شود و کیفیت/امنیت عملیاتی باید پیش از انتشار عمومی تست شود. تماس گروهی پیاده‌سازی نشده است.
- زمان‌بندی سمت سرور: migration 004 تابع `dispatch_scheduled_messages()` را می‌سازد و در صورت فعال بودن pg_cron تلاش می‌کند هر دقیقه آن را اجرا کند. پس از اجرای migration، در SQL Editor بررسی کن job با نام `arad-chat-scheduled-dispatch` در `cron.job` وجود دارد. اگر pg_cron در پلن/پروژه فعال نبود، باید زمان‌بندی Supabase Cron را دستی به تابع/Edge Function متصل کنی؛ در غیر این صورت پیام‌ها خودکار ارسال نمی‌شوند.
- PWA فقط پوسته را cache می‌کند؛ API و پیام‌ها عمداً cache نمی‌شوند.
- آمار فایل داشبورد بر اساس جدول metadata است و تا زمان ثبت metadata در آپلودها، حجم واقعی Storage را نشان نمی‌دهد.

## محدودیت‌های باقی‌مانده
- تماس صوتی/تصویری نسخه آزمایشی P2P است؛ بدون TURN ممکن است پشت بعضی NATها/شبکه‌ها شکست بخورد. تماس گروهی وجود ندارد.
- فهرست دستگاه‌ها نشان‌دهنده مرورگرهایی است که این نسخه ثبت کرده؛ Supabase Auth نشست‌های فعال کامل را از طریق API کلاینت در اختیار این رابط نمی‌گذارد.
- اعلان Push در زمان بسته بودن سایت، اجرای امن ربات، فروشگاه اجرایی ربات، پاک‌سازی فیزیکی خودکار پیام منقضی و broadcast ایمیل/Push هنوز پیاده‌سازی نشده‌اند. پیام همگانی فعلی فقط اعلان داخل دیتابیس ایجاد می‌کند.
- پنل مدیریت نیازمند deploy توابع Edge و تعریف امن اولین مالک است. هیچ مالک پیش‌فرضی در کد وجود ندارد.

## نکات مهم
- Supabase Auth ایمیل را یکتا نگه می‌دارد؛ اما تشخیص اینکه دو ایمیل متعلق به یک انسان‌اند بدون احراز هویت اضافه ممکن نیست.
- رایگان بودن به سهمیه سرویس‌ها وابسته است و نامحدود/همیشگی تضمین نمی‌شود.
- قبل از انتشار عمومی باید سیاست‌های RLS، عضویت گفتگوها، آپلود فایل، محدودیت نرخ OTP و پیام‌ها، ضداسپم و عملیات مدیریتی توسط توسعه‌دهنده بازبینی شوند.


## راه‌اندازی تماس و زمان‌بندی
- تماس: HTTPS لازم است (localhost برای توسعه مجاز است). در صورت شکست تماس بین شبکه‌ها، TURN server لازم است؛ STUN به‌تنهایی تضمین اتصال نمی‌دهد.
- زمان‌بندی: پس از migration 004، وضعیت pg_cron را با `select * from cron.job where jobname='arad-chat-scheduled-dispatch';` بررسی کن. اجرای تابع باید با مالک دیتابیس انجام شود و تابع برای کاربران عادی قابل فراخوانی نیست.
- دستگاه‌ها: رکورد هر مرورگر با کلید تصادفی محلی ثبت می‌شود؛ پاک‌کردن داده‌های مرورگر باعث ثبت دستگاه جدید خواهد شد.
- پنل مالک: UUID حساب مالک تأییدشده را از مسیر امن در `staff_roles` با role=`owner` ثبت کن. هیچ‌وقت service_role را در `.env` فرانت‌اند قرار نده.

### جایگزین زمان‌بندی در صورت نبود pg_cron
تابع `scheduled-dispatch` را با `supabase functions deploy scheduled-dispatch --no-verify-jwt` منتشر کن و Secret با نام `SCHEDULER_SECRET` در Edge Function تنظیم کن. سپس در سرویس زمان‌بندی مورداعتماد خودت (یا Supabase Cron با HTTP request) هر دقیقه به آدرس `/functions/v1/scheduled-dispatch` درخواست POST بفرست و هدر `x-scheduler-secret` را با همان Secret قرار بده. این Secret را در مرورگر یا فایل `.env` قرار نده.


## نسخه ۰٫۵ — تکمیل پنل مالک و تماس

### موارد اضافه‌شده
- بخش «پنل مالک» در پنل مدیریت با شناسه نمایشی 666 و عنوان «پشتیبان اراد چت».
- نمایش هویت حساب مالک واردشده و وضعیت نقش مالک.
- عملیات حذف دائمی کاربر فقط برای مالک، با تأیید دو مرحله‌ای و جلوگیری از حذف حساب خود مالک.
- رابط تماس صوتی با عنصر صوتی مستقل، بی‌صدا/فعال‌کردن میکروفون و پایان تماس.
- زمان‌سنج تماس بی‌پاسخ و وضعیت تماس ازدست‌رفته.
- پشتیبانی اختیاری از تنظیم TURN از طریق متغیرهای محیطی.
- Migration شماره 005 برای محدودکردن تغییرات سیگنالینگ تماس به طرفین مجاز.
- فایل `supabase/OWNER_BOOTSTRAP.sql` برای تعیین امن اولین مالک از طریق SQL Editor.

### راه‌اندازی پنل مالک
1. حساب مالک را با ایمیل واقعی در برنامه بساز و ایمیل را تأیید کن.
2. در Supabase به SQL Editor برو.
3. فایل `supabase/OWNER_BOOTSTRAP.sql` را باز کن، ایمیل خودت را جایگزین مقدار نمونه کن و اجرا کن.
4. Edge Functionهای `admin-console` و `admin-action` را منتشر کن و Secretهای سمت سرور Supabase را تنظیم کن.
5. با همان حساب مالک دوباره وارد برنامه شو.

### راه‌اندازی تماس
1. Migrationهای 001 تا 005 را به ترتیب اجرا کن.
2. Realtime را برای جدول‌های `call_sessions` و `call_ice_candidates` فعال نگه دار (Migration 004 تلاش می‌کند آن‌ها را به publication اضافه کند).
3. برنامه باید روی HTTPS یا localhost اجرا شود تا دسترسی میکروفون/دوربین مجاز باشد.
4. برای شبکه‌هایی که STUN کافی نیست، یک TURN معتبر تنظیم کن و مقادیر `VITE_TURN_URL`، `VITE_TURN_USERNAME` و `VITE_TURN_CREDENTIAL` را در محیط Build قرار بده.

### محدودیت‌های تست
این نسخه از نظر سلامت فایل و بررسی نحوی JavaScript بررسی می‌شود؛ اما بدون پروژه Supabase واقعی، تنظیم ایمیل، انتشار Edge Functionها، TURN و آزمایش با دو حساب/دو دستگاه، عملکرد انتهابه‌انتها قابل تأیید نیست. این نسخه را آماده انتشار عمومی یا دارای تماس تضمین‌شده تلقی نکن.
